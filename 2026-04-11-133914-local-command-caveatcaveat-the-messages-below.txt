❯ Do we have infrastucture to process and extract data in pdf files             
efficiently. This is just a question, dont do anything.                         

⏺ No. The database schema is ready for it (tender_document_sets, raw_documents
  with storage_path and content_type), and the pipeline stage exists in the
  stage tracking system ("acquire docs" at notice scope). But there's no actual
  PDF processing code:

  - No PDF parsing library in Cargo.toml (no lopdf, pdf-extract, pdfium, etc.)
  - No OCR capability (no tesseract integration)
  - No document download logic — Stage 4 (Acquire Docs) is fixture-stubbed

  What you do have that could work:

  - Claude CLI can read PDFs natively — it's multimodal. An agent skill could
  download a PDF to disk and pass it to Claude for structured extraction during
  a PTY session.
  - agent-browser could download PDFs from procurement portal links.
  - The raw_documents table already supports storage_path for file-based storage
   (vs inline payload_json), so the plumbing for "download file → store
  reference → process later" is there.

  The practical path would be an agent skill (not deterministic code) that
  downloads tender documents and uses Claude's PDF reading to extract structured
   data from them.
