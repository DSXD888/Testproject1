## What the Push Prompt Does

The push prompt is a **compact continuation nudge** (~80-130 lines, 8-9 sections) used during execution to:

- Re-orient an agent who has been working on something else and is now joining L5 work.
- Continue a paused L5 session after a context reset.
- Onboard a fresh agent quickly when the full kickoff is overkill (rare for L5 — customs surface is complex; default to kickoff for fresh agents).
- Re-state the work loop in compact form for an agent who already knows the basics.

The push prompt is reused continuously across multiple continuation sessions. It must NOT contain stale instructions. It must always reflect the latest:

- Bead CLI invariants (`br` not `bd`, `bin/br-sync` not raw `br sync`, `bin/br-claim` / `bin/br-complete` wrappers per AGENTS.md Rule 2).
- AgentMail project key (`/Users/zacfarrell/Desktop/Testproject1`).
- Verification commands (Stage Validation Test Gate, AGENTS.md:150-166).
- Work loop steps.
- L5-specific contracts (conservative defaults constitutional, FPO never primary, UK-specificity rule, never greedy descent, compound/specific duty preserved, customs branch divergence is hard blocker, L5→L6 readiness gate 5 conditions).

### 3. Bead Completion Policy (compact, firm)
- Use `bin/br-claim <id>` / `bin/br-complete <id>` — only authorized path (AGENTS.md Rule 2 constitutional).
- Every bead fully completed before moving on.
- Complete = code + tests + checks + committed AND pushed + `bin/br-complete` ran clean.
- If blocked: diagnose, fix yourself, escalate via AgentMail only if blocker is in another agent's code.

### 4. Work Loop (compact, ~10 lines)
1. Check inbox (`fetch_inbox`) → acknowledge messages.
2. `br ready --label l5 --json` → pick highest-priority ready bead.
3. Read bead FULLY → study target files.
4. CLAIM: `bin/br-claim <bead-id>` (atomic — wrapper handles file reservation + Start mail + br update). Override file list with `--paths` if bead lacks a Files section.
5. IMPLEMENT: TDD — extend tests first, then code. Implement ALL of it. No mid-way commits.
6. VERIFY: full Stage Validation Test Gate (cargo full + iterate `crates/daemon/tests/*.rs` + bun + UBS).
7. COMMIT: `git add <specific-files>` + `git commit -m "<bead-id>: <desc>"` + `git pull --rebase && git push`.
8. COMPLETE: `bin/br-complete <bead-id>` (atomic — wrapper verifies pushed, sends Complete mail, closes bead, syncs `.beads/`, releases reservations).
9. LOOP → step 1.

Do not stop to ask what to work on next. Pick the next ready bead.

## When the Push Prompt Becomes Stale

The push prompt becomes stale and MUST be regenerated when:

- The bead corpus changes significantly (new beads added, phase boundaries shift, chokepoint files change).
- The Stage Validation Test Gate changes (e.g., new test command added, AGENTS.md amends the gate).
- The AgentMail project key changes (it shouldn't, but if it does, regenerate).
- A core contract is amended via spec change (e.g., a new conservative-default row added in §1.12, a new customs error code beyond the 10).
- The strategy reorders phases.
- A new chokepoint is identified during execution (e.g., a third edit to `crates/daemon/src/main.rs:5639+` becomes a serial bottleneck).

Regeneration is via re-running step 10 (`/beads-to-execution`).

## Notes for Continuation Agents

When you receive this push prompt:

1. **Do NOT skip the AgentMail registration step.** Even if you think you registered before, run `fetch_inbox` first. There may be messages waiting (especially blocker notices from sibling agents).
2. **Do NOT trust an old `br ready` cache.** Run it fresh — phase transitions change readiness rapidly during L5 execution.
3. **Do NOT assume `git pull --rebase` is unnecessary.** Other agents have pushed since you last worked.
4. **Do NOT mix L5 work with L1/L2/L3/L4 maintenance.** Stay scoped to `--label l5`. Cross-layer maintenance goes through separate beads with separate labels.
5. **Do NOT skip `bin/br-sync`.** It's NOT just `br close <id>`. The .beads/ JSONL files must be synced and pushed for other agents to see the closure. The `bin/br-complete` wrapper does this for you — but if you bypass the wrapper (which is forbidden), you'd need to remember the sync.
6. **Do NOT bypass the wrappers.** AGENTS.md Rule 2 is constitutional. Wrappers are atomic; raw `br update` and `br close` are not.
7. **Do NOT assume the customs surface is "just like L4 sync"** — L5 has 5 recall sources, multi-family expansion, measure-interaction logic, evidence-tiered accuracy. Read the bead description fully; the spec is the tiebreaker.
